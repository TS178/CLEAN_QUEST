# 置物サイズの全端末への配布（1.27）

管理者画面で調整した置物の大きさをJSONファイルに書き出し、GitHubへ取り込んでアプリ更新として配布できます。サーバーや有料サービスは不要です。リアルタイム同期ではありません。

## 管理者の操作

1. 管理者モードでようせいの種類を選び、「すみかのアイテムの大きさ」でアイテムを選びます。
2. 大きさを調整し、「大きさを保存」を押します。ほかのアイテム・種類も必要に応じて調整します。
3. 「配布用設定を書き出す」を押し、`clean-quest-habitat-sizes.json` を保存します。保存前の変更がある場合は先に保存するか戻してください。
4. ファイルを開発担当（Codex／Claude Codeなど）へ渡します。GitHubへの取り込みと公開後、ほかの端末でもアプリを更新すると共通サイズが適用されます。

ファイルには3種類の保存済みサイズと配布設定の版番号だけが入ります。ようせいの名前・育成状況・残高などは入りません。置物の位置と、身に着ける装備の位置・倍率は今回の配布対象に含みません。

## 開発担当の取り込み

最新のリポジトリで次を実行します。

```powershell
node tools/import-habitat-sizes.mjs "受け取ったファイルのパス.json" --check
node tools/import-habitat-sizes.mjs "受け取ったファイルのパス.json"
git diff -- js/habitat-size-defaults.js service-worker.js
```

確認のみの `--check` はファイルを変更しません。本取り込みは `js/habitat-size-defaults.js` の配布設定の版を1つ進め、`service-worker.js` のアプリ版も1つ進めます。種類・アイテム・倍率（25〜250%）が不正、または書き出し時の配布設定が古い場合は取り込みを拒否します。古い書き出しは最新アプリで調整して再度書き出してください。同じ設定なら変更しません。

差分とテストを確認し、通常どおりコミット・プッシュします。ツール自体はコミットやプッシュを行いません。GitHub Pagesへの公開後、利用者はオンラインでアプリの更新を受け入れます。オフラインのままでは新しい設定を受け取れません。

## 端末内の調整との関係

- 1.27の初期配布設定は版0・空です。既存の端末内サイズを引き続き使います。ユーザーが調整した実際のサイズは、書き出しファイルを取り込むまで他端末へ配布されません。
- 新しい配布設定を受け取ると、その版より古い端末内調整は表示に使用しません。以前の端末内データは読み込み時には削除しません。
- 最新の配布設定の上で管理者が調整・保存した値は、その端末でプレビューできます。「配布中の標準に戻す」で現在の配布値へ戻ります。
- ほかの端末へ次の調整を配るには、再び書き出し・取り込み・アプリ更新を行います。

## 首まわりの重なり

スカーフとうみのまもりてメダルを、ペンダント・ポシェットと同じ遮蔽処理に追加しました。頭に重なる部分を頭の後ろへ隠します。静止画・動く描画・撮影用の描画に共通で適用し、管理者による位置・倍率変更にも追従します。

## 検証

- `tests/habitat-sizing.test.mjs`：既存端末の移行、新しい配布値の優先、保存済み設定の出力、配布値へのリセット、不正値／古い版の拒否、取り込み時のアプリ版更新。
- `tests/e2e/admin-shared-sizes.mjs`：管理者画面の保存・実ファイルのダウンロード、未保存変更の扱い、育成データの維持、全9形態のスカーフ／メダル画像の読み込みと重なり。
- `tests/e2e/companions.mjs`：3匹の相棒、置物の調整と再読み込み、オフラインなど既存機能の回帰確認。

PCのテスト用Edgeで確認しています。実機のiPhone／Androidは未確認です。
