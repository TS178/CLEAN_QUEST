# 手足の付け根が離れる表示・震えの修正（1.24）

## 原因と変更

正面イラストを胴体・手足に分割して個別に回転させると、切り口同士の位置がずれ、隙間や段差が見えていた。
元画像にない胴体部分を補完する方式だけでは、動く角度によって切り口が露出する。

`js/pet-skin.js` を追加し、承認済みの正面イラストを１枚の連続した三角形メッシュに貼って動かす方式に変更した。
既存の切り出し画像は、ヒレ・尾びれ・脚を動かす範囲の判定に利用する。隣り合う三角形は頂点を共有し、付け根の動きを抑え、先端に向かって動きを大きくする。
極端な姿勢でも面が裏返らないよう、全ての回転角に対する変形勾配の上限から、形態ごとに一定の変形量上限を求める。

- 元のキャラクター画像、切り出し画像、装備の取り付け位置は変更なし。
- ３種類・３形態のすべてに適用。管理者・ホーム・すみかは同じ描画を利用。
- 手足の周期・移動速度との連動は既存設定を利用。体の揺れ・左右反転も維持。
- 頭の二重描画を止め、帽子を元の頭の位置に維持。
- ヤドカリ第２形態の17×18pxの小片は独立した脚として回転させず、連続した元の絵の一部として表示。
- 描画にWebGLを使用。使えない端末・コンテキスト喪失時は、分断されたパーツに戻さず元の正面絵を表示する。
- SafariでCanvasのfilterが使えない場合に備え、動きの範囲をぼかす計算は小さいマスク上でJavaScript実装。
- 使い終わった描画のGPUリソースを破棄。動きを減らす設定では従来どおり静止画。
- オフライン用ファイル一覧と配信バージョンを1.24へ更新。

## 確認方法

`preview-pet-joints.html` で全９形態の動きを確認できる。元の静止画との切り替え、左右の向き、動きの速さを変更可能。
このページは育成・購入の保存データを書き換えない。

ローカルサーバーをポート8766で起動し、以下を実行。

```
node tests/e2e/pet-joints.mjs
node --test tests/logic.test.mjs tests/pet-rig.test.mjs tests/ar-math.test.mjs
```

`BCT_URL=http://127.0.0.1:8766/` を設定して `tests/e2e/pet-rig.mjs`・`tests/e2e/iphone.mjs` も確認。

## 検証

- ９形態×32位相＝288姿勢：面の反転なし。元の絵とゼロ変形時の描画が一致すること（色の平均誤差2/255未満）、実際に画素が動くことを確認。
- 振れの両側・左右反転・花飾り＋ポシェットの装着を画像で確認。
- 管理者・ホーム・すみかの描画、描画コンテキスト喪失時の代替表示、動きを減らす設定を確認。
- オフライン再読み込みでも連続描画を確認。確認ページ９形態の描画・スマホ幅・保存データの不変も成功。コンソールエラーなし。
- 基本ロジック・保存・AR計算・リグ設定：47/47成功。
- iPhone向けUAと320〜430pxの画面幅：14/14成功（Edgeによるエミュレーション。iOS実機の確認ではない）。
- 既存リグの通し確認：38/39成功。失敗は「390×844のホームでようせい幅140px以上」で、実測123px。新しい描画の有効／無効の両方で123pxであることを確認。今回の付け根修正ではホームのサイズ処理・レイアウトを変更していない。

スクリーンショットと数値は `tests/e2e/out/pet-joints-fixed.png`、`pet-joints-fixed-reverse.png`、`pet-joints-results.json`。テスト用の独立したブラウザで確認し、利用者の保存データには触れていない。

旧調査記録 `admin-parts-audit-20261016.md` は当時の状態として保存。2026-10-17の修正依頼を受け、今回は共通描画に修正を実施した。

## 利用者からの再指摘とキャッシュ診断

利用者から「ちぎれて見える」と再指摘あり。現在の利用者のタブはブラウザ操作ツールから取得できず、原因を直接確認できていない。数値テストの合格をもって見た目の問題が解消したとは扱わない。

独立ブラウザに旧rig.js・設定・CSSをキャッシュして再現すると、新しい確認ページでも旧描画になる（9形態中、連続描画0形態）。Service Workerが検索パラメーターを無視してキャッシュを返すため、URLに版番号を付けるだけでは回避できない。
`tools/build-pet-joints-preview.mjs` でコード・CSS・正面画像をHTML内に含む `output/design-proposals/pet-joints-1-23/index.html` を作成。旧キャッシュがある状態でも連続描画9/9を確認（`tests/e2e/pet-joints-cache.mjs`）。確認ページには実際の描画方式の状態を表示する。

この再現は原因候補の検証であり、利用者の見ている症状が旧キャッシュによるものと断定する証拠ではない。その後、利用者より接続は改善したがイルカ第3形態・カメ第2/第3形態が震えると報告があった。

## 1.24：震えの修正

1.23試作では、三角形の面積が閾値を下回る瞬間に変形量を1から0.5に切り替えており、連続するフレームの間に不連続な跳びが発生していた。
形態作成時に、各三角形の変形勾配について全回転角を覆う上限を計算する方式へ変更。フレーム中は常に同じ倍率を使い、手足は正弦波に沿って連続的に動く。
勾配のノルムを0.48以下に抑え、三角形の縮みすぎ・裏返りも防ぐ。

9形態それぞれ513連続位相で倍率が変化しないこと、頂点移動の加速度が0.05px/step²未満であること、三角形の面積比が0.25以上であることを確認。既存の288姿勢・元画像との一致・実際の画素の移動・オフラインなどの確認も成功。
新版の独立確認ページは `tools/build-pet-joints-preview.mjs` から `output/design-proposals/pet-joints-1-24/index.html` に生成できる。

1.24の通し確認は単独再実行で123/123成功。装備編集の専用テストも成功。
初回の並行検証では、capture/dressup/photo/appの初期化時に依存値が未定義となる例外が記録された。5回の読み込み順診断と単独の通し再実行では再現せず、原因は未確定。以前の組み込み検証でも類似例外があり、この修正で解消したとは扱わない。
キャッシュ検証の最初の試行ではService Workerのready待機が完了せず中断した。キャッシュ再現テストは「インストール済み」を前提に明示的に登録し、待機に15秒の上限を設けた。起動時登録の検証とは分けている。
